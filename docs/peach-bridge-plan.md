# Peach 番号下载与入库闭环

## 验收目标

在 MoviePilot Peach 专区输入番号，调用已配置资源站点的原始搜索，展示明确匹配的资源。用户手动选中后由 MP 默认或指定本地下载器获取；完整下载后通过受鉴权的 Peach 桥接接口登记，MP 展示真实馆藏与任务状态。不依赖 TMDB 识别，不引入自动订阅。

## 边界

- MP 保留现有管理员、站点及下载器授权；浏览器不持有 Peach 令牌或站点凭据。
- 番号与资源候选由服务端校验；候选身份在服务端保留，下载请求不能注入任意资源地址。
- 桥接任务独立记录并恢复；下载提交不明确时显示待处理，不能自动重提。
- 专用下载根与 Peach 导入根挂载同一份文件，只传相对路径；限制路径、符号链接与媒体类型。
- Peach 复用自己的扫描、账本与路径映射，不能由 MP 直接写数据库。入库接口按 request_id 幂等。
- 文件整理只由指定一方负责；本阶段只登记、不重命名、移动或删除下载源。
- 未完成文件不能标记已入库；回调失败可重试，只有 Peach 确认馆藏记录存在才完成。

## 实施与责任

1. Peach：专用令牌鉴权的番号馆藏查询、幂等导入和结果查询接口，复用现有扫描与 Windows 账本路径映射。
2. MP 后端：typed bridge service/ports、原始搜索、下载提交/追踪、Peach HTTP adapter、隔离状态存储和受权限约束 API。
3. MP 前端：Peach 路由、导航、番号搜索、人工下载确认、任务状态和馆藏展示；处理未配置、断线与错误。
4. 集成：统一响应与路径契约，用生成的测试媒体和临时账本证明完整调用链；真实站点与下载器账户存在时才进行相应外部验收。

## 验证与交付

行为测试覆盖准确番号匹配、权限、候选不可伪造、幂等与提交不确定、重启恢复、路径越界、未完成下载、Peach 失败重试、最终馆藏。运行各仓库规定的相关门槛，必要时全套；保留上次原版可复现的环境失败证据，不能弱化断言。前端须通过类型、lint、构建和组件测试。全部候选安排一次独立审查，后续只对受影响检查重新验证，不重复全面审查。只交付本任务分支，不修改真实媒体/账本、其他服务或原先已关闭的测试实例。
