# Peach 桥接第一阶段

MP 负责番号站点搜索及手动提交下载，Peach 负责文件识别、入库和馆藏；不创建 JAV
全局媒体类型，不调用 TMDB，也不写普通影视下载/整理历史。普通登录和真实站点凭据仍然必需。

## 部署配置

- `PEACH_URL`：MP 后端请求 Peach 的内部 HTTP(S) 地址，专用令牌仅发送到此地址。
- `PEACH_PUBLIC_URL`：可选的浏览器访问 HTTP(S) 地址；留空沿用 `PEACH_URL`。例如容器内配置 `PEACH_URL=http://peach:8900`，SSH 转发访问时配置 `PEACH_PUBLIC_URL=http://127.0.0.1:18900`。馆藏链接先验证属于内部地址，再转换为浏览器地址；两种地址均不接受凭据、查询参数或片段。
- `PEACH_TOKEN`：对应 Peach 的 `PEACH_MOVIEPILOT_TOKEN`，使用独立随机密钥。
- `PEACH_DOWNLOAD_ROOT`：MP 与下载器能写入的本地绝对专用目录。
- Peach 的 `PEACH_MOVIEPILOT_IMPORT_ROOT` 必须映射到同一份共享文件内容。

MP 会在专用根目录中为每个任务创建随机子目录；Peach 只收到相对根目录路径。
该根目录不能与 MP 任何普通媒体下载目录重叠，也不要另行添加至影视目录监控。
普通整理工作流对该根目录中的本地文件直接拒绝。Peach 入库只登记、扫描，不移动或删除文件，
已完成文件继续位于下载器路径以便做种。未配置时桥接禁用，不影响原有功能。

## 接口与操作

响应均为 `success/message/data`。所有接口要求有效登录；所有 POST 另要求管理权限。

| 接口 | 行为 |
| --- | --- |
| GET `/api/v1/peach/status` | 配置及连接状态，不泄露地址、令牌和路径 |
| POST `/api/v1/peach/search` `{code,sites?}` | 用 Peach 权威规则规范化番号，再直接搜索站点；只缓存精确边界匹配资源 |
| POST `/api/v1/peach/downloads` `{candidate_id,downloader?}` | 用户手动选择不可预测候选标识，不能提交任意资源 URL 或凭据 |
| GET `/api/v1/peach/tasks` | 只读取持久任务 |
| POST `/api/v1/peach/sync` | 核实真实下载状态、完成比例和路径后幂等入库 |
| GET `/api/v1/peach/library?code=...` | 查询 Peach 馆藏摘要，省略番号返回受限最近馆藏 |

配置齐全时，既有调度器每 60 秒核实已提交任务并入库，用户关闭页面也会继续处理。
未配置不注册该任务、不访问 Peach。用户点击同步可即时核实；后台和刷新均不会搜索或提交新下载。
候选在服务端保留 30 分钟且最多 2000 条，私有状态位于 `CONFIG_DIR/peach-bridge/state.json`，
文件权限为 0600、父目录 0700，包含内部资源凭据，应按敏感配置备份与保护。任务不写业务数据库。

同站同番号同资源链接使用稳定摘要原子占有，重复点击或重新搜索不会重复提交。提交前还会
查询下载器中的真实种子哈希，已有资源不接管、不重投。下载副作用前已持久化任务意图；
若程序中断或下载器未返回可信标识，任务转为 `needs_attention`，需人工在下载器核实，
不会自动重试下载。仅 Peach 入库网络失败可以使用同一 request_id 自动重试。

完成判定要求精确下载器和 hash、100% 进度、原始下载器明确完成状态、无剩余字节，以及存在于专用任务目录内的
可信绝对路径；越界、兄弟任务路径、符号链接及缺失文件均拒绝。Peach 还会独立验证文件集合和番号。
馆藏链接只能指向配置的 Peach 来源，站点下载链接、Cookie、Token 不传给浏览器。

## 验收限制

自动化验证使用受控站点、下载器以及临时 Peach 库，不消耗真实站点下载额度。
使用真实站点前须部署同内容的共享目录，并用已有授权账号验证站点资源与下载器兼容性。
原有主服务及此前停用的测试实例不会因此自动启动。

当前自动完成确认支持 qBittorrent 和 Transmission。rTorrent 现有查询缺少 hash-checking
事实，因此第一阶段会在下载副作用之前明确拒绝 rTorrent 或未知类型；该下载器尚不在闭环支持范围内。
请选择已启用的 qBittorrent/Transmission 默认或指定下载器。

## 验证证据

独立审查覆盖 MP 后端、前端和 Peach 入库接口。发现的完成状态、入库重试及权限问题已按行为回归闭合；完成事实由 qBittorrent / Transmission 原始状态、剩余字节和进度共同确认，未知状态不允许入库。

跨服务验收通过正式 MP 路由、编排、持久状态和 HTTP 客户端调用 Peach 正式入库路由与扫描器。临时账本登记了一条生成的视频：未完成时零入库，网络中断和 Peach 执行失败保留同一任务重试，成功后 MP 可查询馆藏；重复搜索只提交一次下载，重建服务后任务仍存在。站点与下载器使用受控夹具，未调用真实账号。

前端组件、权限、类型、lint 与 production build 通过；后端 mypy、改动文件 pylint 和架构策略通过，组合镜像已构建，源码站点离线检查通过。Peach 全套为 7,093 通过、146 跳过、3 失败，失败均在原版复现。MP 全套为 17,398 通过、29 跳过、15 失败；其中一项镜像更新环境变量污染在清除该变量后单项通过，其他为原版可复现的音乐文件变更、扫描缓存和 shell 环境机制。没有为通过测试修改这些无关断言，也不宣称全套全绿。

真实站点搜索与下载器服务尚需在配置共享目录和授权账号后验收。本次没有启动之前已停止的主服务或测试实例，没有修改真实媒体与账本。
